# poll：文件描述符就绪等待

共享 ABI 在 `kernel/fs/poll.h`，系统调用编号为 49：

```cpp
struct pollfd { int fd; short events; short revents; };
int poll(struct pollfd *fds, int count, int timeout_ms);
```

`events` 指定 POLLIN/POLLOUT；`revents` 返回就绪事件。POLLERR、POLLHUP、
POLLNVAL 无需请求也会返回。返回值是 revents 非零的数组元素数量，同一 fd
出现两次会分别计数。负 fd 被忽略且 revents 清零；未打开的非负 fd 返回
POLLNVAL。未知请求位忽略。count 限制为 0..NOFILE，count=0 允许空指针。

超时为 0 时只检查一次；负数无限等待；正数以毫秒计算绝对截止时间。
计时来自 QEMU virt 的 10MHz timebase，等待由现有时钟唤醒，所以超时向后
取整到可用通知时刻，正常情况下精度受 100ms 定时器间隔约束。无关事件
不会重置截止时间。没有事件超时返回 0；参数/复制失败或停止、终止信号
中断等待返回 -1，本项目没有 errno。poll 不像 read 那样在停止/继续后自动
重放；调用者可重新查询状态。

## 就绪查询

| 对象 | POLLIN | POLLOUT | 关闭与错误 |
| --- | --- | --- | --- |
| inode 文件 | 可读打开即可报告，包括 EOF | 可写打开即可报告 | 按描述符访问权限过滤 |
| 管道读端 | 有数据，或写端已关闭 | 无 | 写端关闭报告 HUP，可先读完剩余数据 |
| 管道写端 | 无 | 有读端且缓冲有空间 | 读端关闭报告 ERR |
| TTY / PTY slave | 行规程有完整记录或满足非规范阈值 | 输出后端有空间 | 挂断后报告 IN/HUP |
| PTY master | 有输出缓冲数据 | slave 输入缓冲能接受输入 | slave 关闭后报告 IN/HUP，允许先排空输出 |

规范输入的 VEOF 即使不产生数据字节，也会报告可读，让下一次 read 返回 0。
非规范输入在 VTIME=0、VMIN>0 时使用 VMIN 阈值；其余情况至少有一个输入
槽才报告可读。VMIN=0/VTIME>0 的 read 超时不属于 poll 的输入事件。
VMIN 大于行规程容量时，poll 的阈值可能始终无法达到；使用 poll 的程序应
选 VMIN=1（当前代理采用的配置）。

UART 后端查询软件发送队列空间；PTY slave 输出保留最多两个输出字节的
空间（换行可能转换为 CRLF）。就绪是一个瞬时快照，不预留缓冲或锁，不保证
任意长度的读写都不等待；并发读取者可能抢先取走数据。当前代理采用非阻塞批量读写，短写保留未完成部分，EAGAIN 后重新等待事件，
避免大块阻塞写挡住另一个方向。详见 [非阻塞 I/O](nonblocking.md)。

## 按对象登记的等待项

实现采用与 Linux poll_table 相近的登记/查询/通知/清理流程，但继续复用本项目
按通道地址散列的 WaitChannels，尚未改成设备内嵌的 Linux wait_queue_head_t。
不再有全局 io_epoch 或全局 poll 广播通道。

- `xv.sync::PollTable` 是设备可见的登记接口，带本次查询的事件掩码。设备在
  查询状态前调用 watch(channel)，可以在持有自身状态锁时登记，不会睡眠。
- 每次系统调用拥有一个 `PollWait`，保存自己的 triggered 状态、订阅存储和
  可选截止时间。内部 PollTable 适配器将设备登记请求转给该上下文。
- 每个 `PollEntry` 连接一个对象通道与一个 PollWait。条目进入对应通道的
  bucket 链表；wakeup 只通知 channel 相等的条目，即使哈希碰撞也不会通知
  不相关对象。同一上下文对重复通道去重，不同调用可以订阅同一个通道。

各对象使用现有的条件通知通道：管道读端订阅读通道、写端订阅写通道；TTY
订阅行规程通道，可写查询还登记输出后端；PTY master 订阅输出通道及需要
的 slave 输入空间通道；UART 可写查询订阅 TX 通知。部分关闭与数据事件
共用一个对象通道，所以允许同一对象上的无关事件通知；没有事件键级别的
精细过滤。设备查询不消费输入，也不执行 SIGTTIN 等实际读取访问检查。

## 登记与睡眠的竞态

第一次扫描将 PollTable 传给文件对象，先登记对应通道，再在对象锁保护下
检查条件。后续扫描只查询状态，复用已登记的等待项。

通知在 bucket 锁下调用 PollWait::notify，再取得目标进程锁，设置 triggered；
如果进程正睡在这个上下文上，就清除 chan 并放回运行队列。等待入口同样在
进程锁下检查 triggered 和待处理信号，再设置 Sleeping 并切换调度器。

因此，查询后、睡眠前收到通知，会使 triggered 检查跳过睡眠；设置 Sleeping
后收到通知，则直接将进程唤醒。多个通知合并成一次触发，唤醒后重新扫描
所有 fd。只在切换前后持有进程锁，不携带设备锁、bucket 锁或定时锁跨调度。

## 截止时间与生命周期

正数超时单独登记到有限等待的截止时间链表。hart 0 的定时通知只扫描该链表，
对到期调用发送一次通知并移除定时项；无限等待不会因为系统时钟或其他对象
的普通 wakeup 周期性醒来。现有 100ms 时钟粒度保留，尚未采用高精度定时器。

sys_poll 显式保留被查询的 File 引用，防止端点和通道在等待项存续时释放。
订阅节点按需使用分配器页，分配接口不睡眠；超时为零的查询不分配订阅页。
所有返回路径，包括就绪、超时、信号、复制错误和分配失败，均由 PollWait
析构撤销定时项与订阅，再释放存储。订阅清理与通知由同一个 bucket 锁互斥，
定时清理与到期通知由定时锁互斥；所有回调结束后才释放上下文页。
PollWait 的析构先于文件引用释放，避免对象已销毁而等待项仍引用其通道。

当前没有共享文件描述符表的用户线程；每个调用对进入时捕获的文件对象进行
查询。仍保留 count<=NOFILE 的限制，不提供 epoll 或持久订阅接口。

## 使用与验证

`user/apps/pty/pty.cpp` 用一个父进程同时 poll 实际终端输入、master 和实际
终端输出，只 fork 运行内层程序。输入/输出待转发缓冲分别保存，master 挂断
时先排空输出，再恢复外层终端；Ctrl-] 主动断开。

运行 `ptytest poll` 检查 ABI、毫秒超时、普通文件权限、管道满/空/EOF/错误、
PTY 两个方向的背压、规范 EOF 与 VMIN、128 次跨进程握手、多个同时等待者、
无限等待被信号打断。`poll_1cpu` / `poll_3cpu` 运行相同契约；PTY 单核/三核
交互测试另外检查改写后的代理及 Ctrl-C、Ctrl-Z、fg/bg、退出恢复。

原生 process_storage_contract 还检查：单次调用订阅多个对象、重复通道去重、
两个调用共享对象、无关队列与时钟不通知、通知早于睡眠、定时只通知到期
调用、分配失败、待处理信号，以及并发通知/超时/撤销 500 次后的资源回收。
