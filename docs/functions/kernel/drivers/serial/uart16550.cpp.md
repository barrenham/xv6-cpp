```doxygen
@fn int xv::drivers::Uart16550::transmit(const char *data, int count, bool nonblocking)
@brief 16550 串口：向输出后端完整提交一个转换单元或小块。
@param data 指向或引用的对象/缓冲；其生命周期必须覆盖本次调用。
@param count 请求传输的字节数上限；成功与错误约定见本函数的返回分支。
@param nonblocking 为真时，资源暂不可用不得进入睡眠等待。
@details 先用发送睡眠锁串行化写入，非阻塞时只尝试取得它；状态锁保护环形队列。整块空间足够才入队并 pump；空间不足则释放状态锁后可中断睡眠，保证转换单元不会只接受一半。
@details 调用/构造表达式的文本次序（分支内不一定全部执行）：`detail::process_killed` → `tx_lock_.try_acquire` → `tx_lock_.acquire_interruptible` → `writer` → `tx_state_.acquire` → `pump` → `tx_state_.release` → `detail::prepare_interruptible_sleep` → `detail::sleep_process`。
@details 本函数可见的状态更新包括：`tx_data_[tx_written_++ % TxCapacity] = data[i];`。局部临时变量与对象字段应按作用域区分。
@details 需要特别跟踪的条件：`count <= 0`；`static_cast<unsigned>(count) > TxCapacity || detail::process_killed()`；`nonblocking`；`!tx_lock_.try_acquire()`；`!tx_lock_.acquire_interruptible()`。这些条件决定检查、重试或提前返回路径。
@note 源码中出现的锁操作：`tx_lock_.try_acquire` → `tx_lock_.acquire_interruptible` → `tx_state_.acquire` → `tx_state_.release`。顺序包含分支和释放动作，不表示这些锁同时持有。
@pre 等待路径必须遵守“条件锁下登记、释放条件锁后真正睡眠”的协议；不能携带无关自旋锁进入调度。是否可中断由具体登记入口决定。
@return 各分支实际返回：`count == 0 ? 0 : -1`；`-1`；`-EAGAIN`；`count`。应结合上面的条件检查区分正常值、空值和错误值。
```
