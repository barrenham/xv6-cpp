# 目录枚举接口

`getdents64(fd, buffer, count)` 通过已有 File/IoObject 后端取得目录记录，
普通文件、字符设备、管道等返回 -1。结构定义在 `kernel/io/dirent.h`，
用户声明在 `user/runtime/user.h`。字段布局依据
[Linux dirent64 定义](https://github.com/torvalds/linux/blob/master/include/linux/dirent.h)：
64 位 inode、64 位有符号后继 cookie、16 位记录长度、8 位类型，以及
以 NUL 结束的名称。名称从第 19 字节开始，每条记录补零对齐到 8 字节。
这里沿用本项目的系统调用号，并不提供 Linux 二进制系统调用 ABI。

ext3 通过 `FileSystem::next_directory` 直接遍历可变长磁盘目录项，返回
最多 255 字节的完整名称、32 位原始 inode 和对应 d_type。旧后端转换
兼容目录记录，未知类型使用 DT_UNKNOWN（0）；它们的 inode 编码范围
仍取决于原有目录记录。procfs 使用打开时已经生成的目录快照，不在每次
读取时重新枚举进程。

一次调用只返回完整记录。缓冲放不下第一条记录时返回 -1；已经写入前缀
后空间不足或后续复制失败，则返回成功前缀的字节数。失败的当前记录不
推进偏移，下一次调用从它继续；EOF 返回 0。所有填充字节清零，不向用户
暴露未初始化的内核栈内容。缓冲地址无需按 8 字节对齐，解析时推荐使用
对齐缓冲。

每个独立 open 可以选择原来的 16 字节 dirent/read 接口，或 getdents64。
第一次成功读取后固定所选方式，混用返回 -1，避免把兼容字节偏移当成
ext3 原始目录 cookie。dup/fork 共享方式和进度，新 open 独立选择。
`fdinfo` 的 pos 显示当前 cookie；目录 cookie 不能当作普通文件字节偏移。

VFS 按所属后端的 name_max 解析组件：ext3 精确匹配最多 255 字节的名称，
超长组件失败，不会别名到合法前缀。原 xv6 格式以及使用兼容目录记录的
后端保留历史 14 字节名称规则；rename 对组件执行严格长度检查。
MAXPATH 现为 4096（含 NUL），因此最多接受 4095 字节路径。符号链接展开
也使用这一上限，最多 16 次展开。挂载管理仍使用原 path[128] 记录及其
既有挂载点限制，普通文件路径的扩展不改变 mountinfo ABI。

lookup_parent 保留默认 14 字节原始输出缓冲契约。需要完整名称的内核调用
显式传入容量（通常为 256）；放不下时返回失败，不写过调用者缓冲。

ls、ps、getcwd 和 shell 补全使用共同 DirectoryReader 解析变长记录。
ls 使用完整名称重新查询属性，块设备显示 b；getcwd 按完整名称核对父目录
身份。用户态较大的 MAXPATH 缓冲改为静态暂存，避免挤占一页用户栈。
这些程序没有用户线程；暂存内容不作为返回指针逃逸。补全表按名称容量
分配，最多容纳 128 个 255 字节名称及目录斜杠，不按整条路径放大。
交互命令行仍有原来的 512 字节上限；更长路径可由程序直接传给系统调用。

验证覆盖四种后端、坏用户地址、过短缓冲、逐条提交与失败前缀、共享进度、
EOF、两种读取方式的隔离、记录边界和零填充。ext3 原生模块及单核/五核
QEMU 额外读取两个共享前 254 字节、末字符不同的 255 字节名称，核对
完整名称和类型。相关检查是 fs_contract、ext3_volume_contract 与 devfs_[15]cpu。
