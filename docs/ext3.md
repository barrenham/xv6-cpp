# ext3 文件系统模块

ext3 已作为文件系统后端接入 `xv.fs`，新建系统镜像默认采用 ext3，实际根盘
也已完成转换及系统程序更新，原始完整镜像和更新前镜像均保留为仅所有者
可读写的备份。109 项检查已有通过结果；完整范围、重跑记录和验证限制见
[验收记录](ext3-dev-proc-acceptance.json)。

## 创建、转换与安装程序

`XV_FILESYSTEM` 可选 `ext3` 或 `xv6`，仅控制新建镜像。已有根盘不会因改变
构建配置而被重建。独立创建原 xv6 格式的镜像：

```bash
build/dev/mkfs new-xv6.img --manifest build/dev/fs-manifest.tsv --filesystem xv6
```

省略 `--filesystem` 时，`mkfs` 默认创建标准 ext3 镜像。初始格式由
e2fsprogs 的 `mke2fs` 建立，文件和元数据经内核共用引擎写入，再用
`e2fsck -fn` 独立检查后发布。两种格式的失败创建都不覆盖既有输出。

已有根盘的离线转换：

```bash
python tools/convert_rootfs.py --image data/rootfs.img --mkfs build/dev/mkfs --filesystem ext3
```

工具锁定原镜像，逐项比较内容、硬链接、符号链接、属主、权限及设备号，
将精确的原始字节保存为 `*.before-convert-*.img`，同步备份后原子替换。
候选镜像检查失败时保留原盘。`--dry-run` 完成候选构建及比较，但不发布。
已有账户记录按原字节保留，不应用旧 `/data` 导入工具的 home 路径重写。

安装新编译的 user 程序仍使用原来的更新入口，现可识别两种磁盘格式：

```bash
cmake --build --preset dev -j6
cmake --build --preset dev --target rootfs-update
```

该更新只替换清单管理的系统程序，保留账户及用户文件，并产生完整备份。
Python 的 ext3 编辑器通过 `libext3_image.so` 调用内核同一磁盘引擎，不另写
一套 ext3 编码。自定义宿主构建目录可用 `XV_EXT3_LIBRARY` 指定该库的路径。

## 模块与依赖

- `xv.fs:journal`：不依赖磁盘格式的事务接口和 `Transaction`。
- `xv.fs:xv6_journal`：保留原 xv6 日志实现；相关状态机没有改变。
- `xv.fs:ext3`：内部 `Ext3FileSystem`，实现公共 `FileSystem` 协议，管理
  inode 引用、睡眠锁、权限检查、用户复制和 JBD 事务容量。
- `xv.fs:disk`：读取超级块选择具体磁盘后端；inode 的 owner 仍为具体后端。
- `service.cpp`：分别装配根盘和数据盘，公共 `journal()` 跟随根盘格式，
  数据盘通过 `Transaction::secondary` 接入。

`ext3/volume.*`、`mutate.cpp` 和 `jbd.*` 是共享磁盘引擎。内核只有模块后端
调用它们，宿主测试可用同一实现直接读写 e2fsprogs 创建的镜像。块缓存维持
1024 字节接口，ext3 适配器拆分 1、2、4 KiB 块的 I/O。设备容量来自 VirtIO
配置空间，并以配置 generation 校验 64 位扇区计数，规则见
[VirtIO 1.2](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html)。

## 日志和锁

JBD 使用标准大端日志头、32 位块标签、UUID、提交记录和 revoke 恢复。
数据与元数据都写入日志；提交记录持久化后才 checkpoint 到 home blocks。
恢复分为确认已提交事务、收集撤销记录和重放三个阶段。未提交的撕裂尾部
可以丢弃；含提交记录的损坏事务会拒绝恢复。格式依据
[Linux 日志说明](https://docs.kernel.org/filesystems/ext4/journal.html)中传统
JBD 兼容布局；未实现的 JBD2 特性会拒绝挂载。

暂存块独立于 LRU 缓存，不会固定大量缓存项。单个操作的 savepoint 使用
写时复制，分配失败或日志 credit 耗尽时恢复原暂存块、位图和计数。
同一文件系统的磁盘引擎调用由睡眠锁串行化；事务 begin/end 不持有该锁跨越
系统调用，也不持有自旋锁进行磁盘 I/O。最后一个事务参与者负责提交。
inode 锁在引擎锁之前获取，引擎锁内不等待 inode 锁。

删除最后一个名字会把 inode 放入 ext3 orphan 链，已有打开引用继续可读。
最后一次 release 只撤销内存引用；最后一个事务参与者提交后回收没有打开引用的 orphan，OOM 时保留链供后续事务或 sync 重试。重启时也按批回收 orphan 链。文件内容和链接数每次
修改前重新从暂存视图读取，避免旧 inode 快照覆盖并发更新的链接数。

## 已有验证

`ext3_volume_contract` 在独立 e2fsprogs 生成的 1、2、4 KiB 块镜像上验证：
创建、硬链接、重命名及覆盖目录、目录移动和环检测、255 字节名称、直接至
三级间接块、稀疏扩展、截断后的零填充、设备号编码、打开后删除、orphan
回收，以及逐次分配失败和 journal credit 耗尽时的回滚。每种镜像经
`e2fsck -fn` 检查。提交的每个块写入/flush 中断点分别由共享引擎和
Linux `e2fsck` 恢复，检查数据为完整的新状态或旧状态，且已提交状态不能丢失。

同一测试还通过实际 C++ 模块、磁盘格式选择、VFS 和块缓存执行路径操作，
将结果交给 `e2fsck` 和 `debugfs` 独立读取，并覆盖第二块 ext3 数据盘的
挂载、引用仍存在时拒绝卸载和正常卸载。ext3 的块设备 inode 保留块设备
类型及主、次设备号，打开时通过注册表连接实际 BlockDevice；测试读取
真实根盘超级块，并由独立工具检查持久化节点。设备 barrier 与等待全部事务提交
分别由 `FileSystem::flush` 和 `Journal::sync` 处理，避免卸载等待自己的事务。

一次性 ext3 系统镜像已在 QEMU 单核完成根盘挂载、首次密码设置、登录、
用户程序和页表 smoke 检查，五核完成 `usertests -q`。回归中发现并修复了
跨未映射用户页的失败写入：保留已覆盖的有效字节，同时沿用原来对失败
部分的返回计数及文件增长规则。宿主测试也覆盖该路径。
`O_TRUNC` 通过可失败的 resize 接口处理错误；失败时先解锁，再撤下
描述符、关闭已绑定后端，避免双重释放 inode。单核/五核测试通过只读
ext3 inode 标志强制该路径，重复 400 次并核对内容、大小与 fd 槽。
最终联合检查包括完整 usertests、单核/五核设备与 proc、存储持久化、两种分配器和性能门槛。两个大内存并发启动检查曾超时，串行分别在 11.03/10.15 秒通过；已将这两项设为 RUN_SERIAL，未放宽原有期限。
实际根盘转换已核对 99 个路径并通过独立分配检查；转换后的实际镜像副本
在五核 QEMU 中到达原来的首次设置/登录阶段。原始备份为 `0600` 权限，
转换证据保存在本机 `build/docs/ext3-integration/conversion-proof.json`。
临时镜像还验证了转换锁、路径竞争、重复转换、精确备份、凭据字节保留和
ext3 上的程序更新；QEMU 验证更新后原账户及用户文件保持可用。

## 支持范围与限制

已加入 `getdents64` 的完整目录记录，ext3 直接返回最长 255 字节名称和
原始 inode 编号；旧的 14 字节名称 read ABI 继续保留。两者在每次打开
中选择一种，不混用不同含义的偏移。详见 [目录接口](directories.md)。
VFS 已按后端支持完整名称，ext3 为 255 字节；路径上限为 4096 字节（含 NUL）。
ls、pwd/getcwd、ps 和 shell 补全同步采用新目录记录。测试覆盖嵌套长名称、
硬链接、重命名、符号链接、超过 2800 字节的物理 cwd，以及 4095/4096 字节
路径边界。原 xv6 格式仍使用 14 字节名称规则。
普通文件偏移仍沿用原来的 32 位接口，seek/ftruncate 限制到有符号 31 位；
磁盘引擎能表示更大的文件，不等于用户接口已开放全部范围。
单次事务最多暂存 256 个块。整棵间接树释放时不再记录将被释放的
指针块内容，只记录位图和保留的父指针。一般 resize 仍采用整次操作的
保存点；超出事务容量会失败并回滚，不能据此宣称无限大小截断均可成功。

孤儿 inode 的运行期回收和挂载恢复采用独立的分批协议：每批最多释放
4 个物理块，并更新对应父指针、i_blocks、位图与计数后提交。即使文件
包含大量间接叶节点，每批仍处于 32 个日志块预算内。正常 unlink 先留下
标准 orphan 链；原事务全部参与者退出并提交后，文件系统才回收没有引用
的 inode。仍被打开的 inode 跳过并保留，最后关闭后的提交再重试。
每个已挂载 ext3 后端预留 3 个提交工作页（共 12 KiB），仅在 JBD 提交
临时分配失败时借用，提交结束归还预留，后端 shutdown 时释放。
磁盘卸载目前保留后端以便再次挂载，因此不立即归还这些常驻页。它们覆盖描述符、
负载副本和超级块工作页，不用于普通修改或增加事务容量。
最后一次 release 不再为读取 inode 分配页面；回收遇到内存不足时，
保留磁盘上的 orphan 链和已完成批次，之后 sync/事务提交可继续，重启也可恢复。

测试使用 300 个间接叶节点的稀疏文件（1 KiB 块时跨三级间接边界），
检查整次截断、逐批预算、逐次内存分配失败回滚、打开后删除和关闭时内存
不足后的重试；恢复批次多个写入/flush 中断点分别由本引擎与 e2fsck 恢复，
并核对最终空闲块和 inode 计数。
时间戳取自板级 Goldfish RTC 的 epoch 秒；设备的低、高位读取由驱动
串行保护，宿主模块契约通过 debugfs 独立核对写入的 mtime/ctime。
外部日志、ACL、ext4 extents、校验日志和 64 位日志
标签不在当前实现内，会拒绝相应格式。

## 最终更新与性能

实际 ext3 根盘通过清单更新了 81 个有变化的系统文件，全部 82 个管理文件经内容和权限核对；清单之外数据、元信息及硬链接关系保持，独立 e2fsck 检查通过。转换前及本次更新前的完整备份均保留。实际账户镜像副本到达原登录入口；用户程序联测仅在另一个重置测试账户的副本中执行，实际凭据未改变。

保留的 xv6 镜像也通过完整五核 usertests。单核/五核各三轮的两种 fork 模式均完成 1000 个子进程，最慢客体计时 2.724 秒，独立命令往返最慢 3.007 秒，五秒门槛未改变。dev 内核 text/只读区 449592 B、data 303304 B、bss 176296 B；这是本配置镜像体积，不是模板或 ext3 单独成本。未测量整体吞吐或最坏栈占用。
