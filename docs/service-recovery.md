# 服务管理器接管与日志轮转

`serviced` 负责配置、依赖和控制接口。每个普通服务有一个独立监护进程，持有
服务子进程、退出状态、通知管道、重试预算和日志管道。服务在独立 session/
进程组中运行；管理器退出不会把信号传播到监护进程或应用。
监护进程使用独立的 16 KiB 匿名映射栈及不可访问的 guard 页，不保留 fork 时
管理器的深层调用栈。信号进入/返回允许有效的 mmap 栈，仍由用户页权限检查
保护信号帧的读写。
exec 的 argv/envp 指针读取同样依据 AddressSpace 的用户映射检查，不再把
普通堆末尾误当作所有用户指针的上界；不可读页、跨页越界和地址溢出仍拒绝。

## 管理器故障

fsboot 发现启动管理器退出后，重新启动 `/sbin/serviced`；启动失败按一秒间隔
重试，登录及既有 FS 服务继续运行。新管理器先取得独占控制 socket，再恢复
核心服务登记并接管原监护进程。配置指纹按实际参数、依赖、重启策略和日志
设置计算，不依赖 C++ 结构体填充字节。

控制 socket 的完整路径决定管理命名空间。其状态保存在 root 所有、0700 的
`/tmp/svc-<namespace>/` 目录，监护端点为 `<service>.sock`。核心服务登记通过
临时文件加 rename 原子替换，接管时先恢复这些身份，避免误判依赖丢失。
同名核心登记可以更新，普通服务不能冒充核心项。

存活服务保留应用 PID、监护 PID、停止状态、oneshot 完成状态、失败退出状态、
重试预算、捕获字节数和轮转次数。管理器停机期间，监护进程继续收集日志和
执行已经配置的重启策略；跨服务依赖沿用最近一次授权，恢复管理后重新检查。

如果配置改变，旧监护进程不会被新配置静默替换。配置中已经移除的服务仍从
命名空间中发现并显示为 unavailable，可以 stop，禁止 start；停止后可重新
load 配置。load 仍要求先停止所有运行中的普通服务。

监护进程本身失联时，不以“控制连接失败”推断应用死亡。遗留端点保留为故障
标记，拒绝再启动一份实例。这种情况需要确认旧应用已经停止后处理故障端点；
本轮不实现监护进程被 SIGKILL 后对其孤儿应用的自动接管。核心 FS 服务失效
仍报告 unavailable，不重建现有挂载或打开文件。

这些记录用于同一次内核运行中的进程故障恢复。`/tmp` 是启动时的 ramfs，
不保存跨系统重启的进程身份，也不承诺内核崩溃后的服务进程恢复。

## 日志

服务 stdout/stderr 写入同一根管道，监护进程按预算读取并写入日志。应用始终
持有管道，不持有日志文件 FD，所以轮转后可以继续写入新文件，无需重启。

```ini
[worker]
exec=/bin/worker --foreground
ready=exec
restart=on-failure
log=/tmp/worker.log
log-max-bytes=65536
log-backups=2
```

`log-max-bytes` 默认 65536，范围 1024..16777216；`log-backups` 默认 2，
范围 1..8。每次写入在容量边界处分割，归档为 `.1` 到 `.N`，超过保留数量的
最旧归档删除。单次收集最多 16 KiB，控制请求也有处理预算，避免持续输出使
控制接口长期得不到处理。写入或轮转失败会停止当前应用并进入既有失败策略。

不同服务应使用独立的规范日志路径，不通过路径别名或硬链接共享同一文件；
配置会拒绝重复的日志路径及保留的 `/tmp/serviced.log`。已有超大日志首次
轮转时保留原内容，旧归档会按保留数量自然淘汰，不主动截断历史内容。

bootstrap 的 `/tmp/serviced.log` 在启动管理器时检查大小，预留 1 KiB 诊断空间，
达到 64 KiB 水位时轮转，保留两份归档。监护进程的内部诊断不写入这个共享
文件。手动启动 serviced 时，其自身诊断仍写向调用者提供的 stdout/stderr。

`servicectl status NAME` 显示监护 PID、累计捕获字节数和轮转次数；
`servicectl log NAME` 读取当前日志。控制协议版本为 2，客户端和管理器应同时
更新。显式 TERM 管理器会先停止受管服务、清理监护进程，再释放控制端点；
意外控制接口故障则保留监护进程供下一管理器接管。

## 验证

`system_extensions_1cpu/5cpu` 中的 servicetest 会强制杀死并重启应用管理器，
检查原 PID、停止状态、失败预算、oneshot 和外部依赖身份；测试拒绝第二个
管理器、权限隔离、配置移除后的服务发现、手动停止与完整退出清理。
追加检查在管理器停机期间杀死应用，确认原监护进程继续重启应用，随后新
管理器接管该次重启及其计数。再杀死监护进程并重启管理器，确认遗留端点
阻止重复启动；测试显式终止旧应用后才删除故障标记。
日志测试在管理器停机前、停机中和接管后产生 stdout/stderr 批次，等待捕获
计数达到完整批次，再逐字节检查保留尾部的内容及顺序、文件容量和归档数量。
最后杀死启动管理器，检查 fsboot 自动恢复核心登记和管理器诊断日志轮转。

所有 QEMU 验证使用独立磁盘副本，不安装到用户的持久根盘。

## FS 线程池迁移后的控制响应预算

管理器的非本地监督循环每轮只轮转处理一项，避免一次同步完成多个 guardian 握手
后才处理控制请求。本地 guardian 继续独立处理自己的服务。控制帧接收等待 1 秒，
覆盖单核调度和 FS 建立连接的开销；超时/关闭连接保留 ETIMEDOUT/ECONNRESET。
单核与五核 system_extensions 全量服务启动、失败重启、接管和日志轮转测试已通过。
