本轮目标是将流程工具应用到除 `kernel/boot` 外的全部内核模块。
**本次接入与源码范围审查已完成，最终 91 项联合检查通过。接口、底层原语和紧凑扫描按逐文件理由保留直接实现；条件配置和性能验证边界见文末。**
网络模块的完整接入见 [网络流程](network-flows.md)，通用接口见 [流程工具](flow.md)。
类主体、原模块接口和公开方法保留；具名阶段与图定义由所属类的私有 Flow 承载。
只有流程编排改为模板图，寄存器访问、字节复制和紧凑数据扫描仍可作为业务原语直接执行。

## 资源与控制协议

- AddressSpace 创建失败按完成阶段反向解除映射。特殊页仅借用，失败与 reset 都不释放它们。
  区域登记失败仍交给 owner.reset；增长映射失败撤销新增区域，大小仅在成功后以 release 发布。
- VirtualAddressPool 统一维护空闲与已占用树及区域属性；容器的预留、属性修改和局部删除在修改前准备分裂节点，复制构造候选池后提交。容器算法保留直接实现，跨页表/物理页的事务继续使用流程图。
  直接扫描和邻接选择规则保持原顺序。
- 管道和 UART 的睡眠路径在条件锁内登记依赖，释放自旋锁后才调度，醒来重新取得锁再检查。
  小管道写先等整体空间，大写允许部分进展；首字节复制失败与非阻塞 EAGAIN 保留。
  字节复制、硬件轮询仍为直接循环，不按字节分派节点。
- poll 仍由词法作用域持有文件引用和 PollWait；图控制扫描与等待，返回时按原次序析构。
  第一轮登记依赖，后续轮次复查状态。
- printk 的 va_start/va_end 留在原调用帧，Context 引用 va_list，不复制游标。
  panic 状态检查及锁协议不变；普通字符和字符串保持直接循环输出。
- ELF 的 PendingImage 和 ExecutableFile 留在 load 的词法作用域。
  文件属性在关闭前保存；成功先交换映像再释放旧映像，失败释放部分候选。
  环境字符串、环境指针数组、参数字符串和参数指针数组共用一个检查空间、对齐并复制的子流程。
  `call<PushBounds, Resume>` 指明返回位置；成功 `return_`，失败 `stop` 结束整次图执行。
  最大调用深度为 1，循环不会增加 C++ 调用栈；两个指针暂存数组保持栈存储且不额外清零。

## 执行成本

这些接入使用 C++20，沿用通用工具的迭代分派执行器。
无子流程调用的图使用 `run<0>`，没有返回栈；ELF 使用 `run<1>`。
执行器使用静态函数指针表索引调用节点，每轮处理返回后再分派下一节点；编译器可能简化部分调用，不能据此假定全部消除。
不启用逐节点执行预算。节点和边可通过 Graph 的类型元数据及 visit 提取，不需要运行时注册。

不能将模板接入视为零成本。每个阶段可能增加索引分派、分支和未内联调用；
子流程增加有界返回位置保存、恢复与检查。模板实例化也可能扩大代码和只读分派表。

## VFS 与内存、虚拟文件系统接入

VFS 的三个图分区位于 vfs 目录；RAMFS 和 DevFS 各使用所属目录的内部图分区。
ProcFS 的私有图定义留在原 cpp 内，复用原 Text、数字转换和类型格式化原语。
原类、模块接口、公开方法签名及对象数据字段保留。

walk 的图明确展示分量循环、末尾创建、链接展开、挂载根切换和失败归还路径。
相对链接保留当前目录引用，绝对链接才释放当前目录并从根重启；
链接目标与剩余路径重叠时先移动剩余部分。十六次链接展开上限与尾斜线语义保持不变。
ancestor 在一百二十八层内迭代，耗尽后按原策略保守拒绝有风险的移动。
rename 始终分别尝试解析两个父目录，所有成功取得的项引用和父引用按原次序归还。
symlink 在事务与 namespace 锁前验证目标长度，写入失败先归还新 inode，再尝试删除新目录项。

挂载共用 MountProtocol 的目录检查和引用回收动作。
运行期挂载与卸载的 Transaction、namespace ScopedLock 保留在原入口词法作用域。
RAM 后端初始化失败仍递增设备号；成功发布才占用动态槽。
卸载先归还路径解析临时引用，再检查 busy，子挂载 pin 也会阻止父挂载卸载。
表记录删除后先释放覆盖点和父目录引用，再分别执行持久后端 flush/根引用归还，
或动态 RAM shutdown/动态槽回收。

RAMFS 保留引用锁与树锁的交接。疑似最后引用先释放引用锁，按需获取树锁，再持引用锁减数；
只有自己新取得的树锁才由图释放。未链接节点和父目录连锁回收使用迭代图，循环不累积调用帧。
目录创建失败回收候选及父 pin 后解树锁；成功仍返回持树锁的 inode。
重命名先安装目标再移除源，目录跨父移动同时转移内部父 pin。
DevFS 的首个 PTY inode 引用接管外部 pin，重复引用释放多取得的 pin，最后引用在锁外归还 pin。
ProcFS 的目标进程检查和 get 中再次快照均保留，不能因为同一次路径解析而合并执行。

普通文件创建的 open_regular 动作在原 namespace ScopedLock 范围运行 RegularGraph；
它属于局部独立图执行，stop 结束这次 run 后返回该动作，并按外层图的下一策略继续。
这不是 flow::call/return_ 子流程调用；工具中显式子流程调用仍由 ELF 的 call/return_ 接入展示。
所有本批独立图使用 run<0>；原生方法间嵌套调用具有固定层级，循环仍在执行器内迭代。
覆盖清单为内部 RegularGraph 单独记录实际调用者、USR 和源码指纹。

页链定位、位图和目录槽扫描、目录插入原语、固定 inode 表初始化、格式化、
批量销毁、单纯引用/锁原语、权限谓词及简单后端委托继续直接实现。

## Xv6 磁盘后端接入

继续新增 16 张图，分别编排 inode/flow.cppm 中的 initialize、allocate_block、allocate、
get、lock、release、reclaim、map_block、truncate、read、write、resize，

分配块先记录位图占用，释放位图缓冲后再清零数据块；
inode 分配先记录磁盘类型，释放块缓冲后再取得缓存 inode。
map_block 的直接地址和间接根分配使用不同节点、复用相同分配/保存动作，
间接根和数据块同时缺失时仍明确执行两次分配。失败不会擅自回滚原算法保留的间接根。

get 在表锁内扫描与发布，返回前统一解锁；lock 仅对无效缓存加载磁盘元数据。
release 的普通引用在原表锁内直接递减并解锁，只有最后无链接引用进入图；
进入图前在表锁内保存设备和 inode 号，再换锁截断内容；
减少引用后不再读取可能已被重用的缓存槽，使用保存的身份清除磁盘 inode 类型。
启动孤儿扫描每轮先释放扫描块缓冲，再在局部事务中通过 lock/release 回收。
块句柄留在原入口词法作用域或对应局部搬运阶段，图不接管隐式堆资源。

读取保留原两个不同错误约定：普通已分配块复制失败返回 -1，
稀疏零块复制失败返回此前字节数，首段失败才为 -1。
写复制失败仍必须记录可能部分修改的块；成功和失败各有独立日志节点，复用同一动作。
完整块段才推进偏移；结束时即使逻辑长度没变也更新 inode，以持久保存新映射。
resize 增长保持稀疏，收缩释放尾块后清零保留块后缀，再发布长度。

硬链接先预留目标链接数，再安装名称，失败重新锁目标撤销增加的计数。
创建目录按点、点点、父名称的次序安装，全部成功后才增加父链接数；
失败把候选设为零链接，更新后解锁归还并回收。
rename 的图区分父别名拒绝、同 inode 成功、覆盖目标、同父原位改名和跨父插入。
安装成功才移除旧名称，并更新被替换目标、目录点点及父链接数。
项锁、父目录锁、项引用分别按原次序清理；相同 inode 的两次引用仍归还两次。

普通 File 共享引用也在文件表锁内直接递减，最后关闭及无效引用检查才进入原 ReleaseFlow。
这样缩短 fork/exit 反复归还共享资源的临界区；复杂回收、锁外关闭和失败语义仍由图连接。

## 进程生命周期与查询接入

本批新增 9 张图，保留 ProcessManager 类与原方法接口。AllocateFlow、ReapFlow、
InitialFlow、ForkFlow、ReparentFlow、ExitFlow、KillFlow、InspectFlow 位于原
lifecycle/process_manager.cpp；WaitFlow 位于原 wait/wait_child.cpp。
它们使用私有 Flow 定义，复用原 ProcessStore、AddressSpace、资源表、组与等待通道接口。
没有为宿主替代模块引入依赖真实 VM 的新分区。

分配先取得带锁描述符和 PID，再申请陷阱帧、配置的系统调用共享页及空映像；
任一步失败统一调用 reap，之后不访问可能已经释放的候选。
reap 依次归还组、陷阱帧、映像、系统调用页、身份与事件状态、父子链，
最后归还描述符及其锁。调用者持进程锁；有父关系时还持 family 锁，未发布候选允许无父。
初始进程建立保留原分配/会话错误诊断，取得根目录引用后发布 Runnable 并解锁。

fork 先在子锁内复制映像、信号帧、寄存器和资源，保存返回 PID 并释放子锁；
再在 family 锁内继承组成员并把子节点挂到父子链尾，最后重新取得子锁发布 Runnable。
子进程可能在父调用返回之前运行甚至退出，因此返回路径只使用保存的 PID。
描述符继承仍逐个保留每个槽位的引用，相同 File 出现在多个槽位时也不合并引用操作。

收养仍只遍历自己的子链，包含僵尸，并按创建顺序移入 init 子链尾。
空子链保持原生快速返回，不进行图分派；非空循环每轮释放子锁后再选下一节点。
exit 的目录引用在动作局部 Transaction 中释放；随后取得 family 锁、收养并唤醒等待者，
再持自身进程锁发布 Zombie、投递子事件并释放 family 锁，带进程锁进入调度器。
init 退出拒绝与调度器异常返回的 panic 语义保留。

wait 的具名阶段直接扫描自己的子链，在每个候选进程锁内判断 PID/组及退出、停止、继续事件。
选中后保持子锁并保存 PID 与编码状态；状态复制成功后才回收僵尸或清除事件。
复制失败解子锁和 family 锁，不消费事件。reap 后不再读取子描述符。
无匹配子进程或父进程已终止返回 -1，WNOHANG 返回 0；
睡眠仍在 family 锁内登记依赖，解锁调度后重新持锁并重扫，不递归增长 C++ 栈。
现有 jobtest 覆盖无效状态地址后仍可读取停止事件、停止/继续事件只消费一次及 WNOHANG。

kill 保留原 PID 谓词查找与 init 保护，持目标锁检查权限、标记并唤醒，解锁后通知子事件。
文件表查询先读取调用者与目标两份凭据快照，即使 root 也不省略读取，
在目标锁内按原权限与容量约束取得文件快照，统一解锁后返回原结果。

不是 flow::call/return_；这种原生调用层级固定，循环仍由各自执行器迭代。

## 系统调用分派与架构陷阱收尾接入
