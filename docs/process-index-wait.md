# PID 索引与子进程事件等待

## PID 与存储生命周期

`PagedProcessStore` 保存两种互补结构：用于完整枚举的双向登记链，以及按正 PID 排序的侵入式红黑树。两者共用登记锁。树链接和不可变 `indexed_pid` 位于存储节点中；进程保存不变的存储归属指针，避免对继承树链接的非标准布局节点使用 offsetof。树节点没有独立堆分配；节点另存注册表归属，release 在任何状态或链表修改前拒绝跨注册表释放。

ProcessManager 先取得正 PID，再调用 `allocate(pid)`，因此身份在描述符被登记前确定。候选持自身进程锁但尚未公开，此时允许取得登记锁发布。重复正 PID 不加入登记链，完整归还描述符和内核栈；负 PID 拒绝。序号仍单调增加，到 INT_MAX 后失败，不新增生产 PID 循环复用。内部存储契约的 `allocate(0)` 保留无身份索引的测试对象，生产进程使用正 PID。

`find_pid(pid)` 持登记锁查树，取得进程锁后复核状态与身份，成功交付已锁定的稳定指针。调用者完成后释放进程锁，或交给 release 消费。kill、正 PID 信号发送、进程文件快照和正 PID waitpid 均使用此路径。进程组身份查询沿用既有 ProcessGroups 索引。

回收先在进程锁内清理业务状态并退役，交出进程锁；然后在登记锁内删除双向链和 PID 树，再取得进程锁，等待此前借出的对象访问完成，最后析构并归还 slab。树键独立于回收时清零的 Process::pid，删除前排序不会变化。不存在持已公开进程锁反向等待登记锁的新增路径。

| 操作 | 复杂度 |
| --- | --- |
| find_pid | O(log N) |
| PID 插入与删除 | O(log N) |
| 已知节点的登记链删除 | O(1) |
| visit / 通用 predicate 查找 | O(N)，保留供完整枚举与内部契约 |

N 为注册表中的进程数。完整 ps/procfs 枚举和组/终端信号的已有遍历策略不在本轮改造范围。

## 每个父进程的三个事件队列

父进程保存退出、停止、继续三个队列的头尾，子进程嵌入每种事件各自的双向链接及成员位。family 锁保护父子关系和全部事件链接，子进程锁保护状态与待报告标志。重复登记不重复入队，事件路径不分配内存。

退出和停止在原发布流程中同步更新事件队列。退出优先，并移除停止/继续队列中的旧成员。SIGCONT 的恢复发生在仅持子进程锁的路径，因此先去重加入单独的延迟通知队列，再由原 NotifyChildFlow 消费，不反向获取 family 锁，也不扫描进程注册表收集继续通知。捕获 SIGCHLD 等信号的通用唤醒仍使用既有信号通知机制。

延迟通知队列由独立锁保护。生产者持子进程锁取得队列锁；消费者持 family 锁固定对象生命周期，取得队列锁摘出节点，释放队列锁后才获取子进程锁。回收在释放对象前撤销残留通知成员。原子通知标志和 NotifyChildFlow 重查循环覆盖通知与消费并发，继续通知独立于 waitpid 状态消费，保留 SIGCHLD 通知语义。

## wait 与 waitpid

- 普通 wait / waitpid(-1)：只检查所请求类型的事件队列。退出队列取首项为 O(1)，不存在退出事件时可直接通过亲属链是否为空判断是否还有子进程。
- 正 PID waitpid：经 PID 树定位，核对目标确实是直接子进程后检查其状态，O(log N)，不会借由 PID 索引等待无亲属关系的进程。
- 按进程组等待：只在事件队列中选择符合组的事件；没有事件时仍可能扫描直接子进程，区分组内有存活子进程与没有可等待子进程。此路径最坏 O(C)，C 为直接子进程数，未增加组成员计数索引。
- 含停止/继续选项的查询会在子进程锁内复核候选，整理尚未完成延迟通知的状态变化；不向用户报告已经被继续操作清除的旧停止事件。

每种事件按登记次序排队，选择时优先退出，然后按选项处理停止和继续；多个符合条件的子进程之间不保证旧亲属链扫描次序。待报告标志仍合并未消费的同类状态，不保存无限事件历史。

状态先复制到用户空间，再清除标志或回收 Zombie。非法状态指针返回失败，事件保持可重试。零状态地址跳过复制。WNOHANG 在有匹配子进程但无事件时返回零，不修改用户状态；没有匹配子进程返回失败。wait 保留原始退出值，waitpid 保留编码状态及原选项。

## 唤醒、重新认领与多核

父进程在仍持 family 锁时登记自己的事件通道，再释放 family 锁并 sleep；醒来后重新取得 family 锁检查事件。每个父进程使用自身队列地址作为独立通道，子事件只通知相应父进程。

退出/停止在获取子进程锁前通知父通道，随后在同一个 family 临界区内发布状态和事件。被唤醒者必须取得 family 锁才能检查，因而不会错过发布，也不会在子锁内反向获取等待桶。延迟继续通知在释放子锁后通知父通道。两者保持现有“等待桶 → 进程 → 就绪队列”锁序。

孤儿转交先移除旧父的事件成员，迁移亲属关系，再按当前状态登记到 init 的事件队列；所有被转交子锁释放后通知 init。已退出但尚未回收的子进程也一起转移。回收和重新认领由 family 锁串行化，事件队列不保留已释放的描述符。

## 验证

`process_storage_contract` 在真实存储实现上验证 256 个 PID 的逆序查询和交错删除、重复/负 PID 失败回滚、跨注册表释放拒绝、查询持锁语义，以及四个写线程反复发布/删除/复用 PID 与并发查询；最终检查描述符和栈页面完全回收。这里的 PID 复用属于存储容器契约，不改变生产序号分配策略。

`process_scaling_1cpu/5cpu` 加入真实客体 `waiteventtest`：160 个直接子进程同时存活、空事件 WNOHANG、非子 PID 拒绝、指定 PID 信号、任意子退出选择、错误 copyout 后重试、按组与任意子停止/继续反复消费，以及 EOF 同时释放剩余子进程后的精确回收。另有退出、停止、继续事件未消费时的孤儿转交，验证 init 的重新登记和最终回收。既有 job、SIGCHLD、信号处理、终端、孤儿与用户回归继续适用。

性能验证保留原 fork 五秒阈值和 1000 个子进程工作量；在无编译、clangd 或其他 QEMU 干扰时单独运行。复杂度变化不等同于所有负载的实测吞吐提升。

本轮最终结果见 [验收记录](process-index-wait-acceptance.json)，详细本机日志位于 `build/docs/pid-wait-events-final/`。
