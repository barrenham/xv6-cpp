# 虚拟区域、缺页与 COW

内核和每个进程使用同一个 `VirtualRegions` 类型登记地址范围；进程的表相互独立，
内核的表属于共享 `KernelPageTable`。区域登记和页表映射是两个阶段：
区域表描述地址归属及权限，PTE 描述当前物理页及硬件权限。

## 区域与生命周期

区域采用 `[begin, end)`，记录 R/W/X/U 权限、用途与是否允许匿名按需补页。
重复覆盖、反向/溢出范围、不合法读写权限及带访问权限的保护区会被拒绝。
元数据按物理页增长，每页容纳 64 个区域，没有固定的每进程区域条目上限；
空元数据页在删除区域后回收。中间删除需要分裂时先准备元数据，失败不修改原表。
显式复制先构建候选表，成功后替换目标；reset/swap 对应地址空间的销毁及 exec 提交。

用户区域包括镜像、栈、保护页、堆及 trampoline/trapframe/PID 等特殊页。
堆的逻辑字节上界由 size 单独记录，页级区域不会放宽 sbrk 的字节边界。
堆不能缩到初始镜像/用户栈下面；下溢返回失败并保持原 break。
内核登记设备窗口、直接映射、trampoline，以及每个栈和相邻保护区。
栈位图用于快速选择槽，完整地址归属同时写入区域表。

地址空间当前只有一个运行线程，修改由所属进程上下文完成；内核区域修改由栈区域锁串行。
查询指针只能在调用者保证稳定的范围内使用，内核对外查询复制区域记录。
原始 PTE 工具仍是内部低层接口，新增映射路径必须先维护区域登记。
这里提供管理基础，没有新增用户态 mmap、文件按需调页或 swap 接口。

## 缺页分类

`FaultOutcome` 同时携带处理结果与成功时的物理地址：

| 结果 | 含义 |
| --- | --- |
| Resolved | 建立了缺失映射或完成了 COW，可以重试 |
| OutsideRegion | 没有合法区域、超过逻辑边界，或该区域不支持匿名补页 |
| Permission | 区域/PTE 不允许此次读、写或执行，包含保护页 |
| AlreadyMapped | PTE 已存在且允许访问，此次异常不是可修复的缺页 |
| InvalidMapping | 页表层级或叶子格式不符合处理约定 |
| OutOfMemory | 无法取得必需的数据页或页表元数据 |

用户态读取、写入和指令缺页分别传递明确的访问类型。先验证区域及逻辑边界，
再检查 PTE；仅合法匿名空洞和合法 COW 写入返回 Resolved。
已有有效映射不会被当作缺失页重复补齐。无法恢复的用户异常终止当前进程，
保留 scause、PC 与故障地址诊断；内核栈保护错误、越界或无法补页仍会 panic。

copyin/copyout/copyinstr 同时验证区域与 PTE，逐页限制剩余有效字节。
copyout 遇到逻辑可写的 COW 页会先取得私有页；真正只读的文本/PID/保护页不能因此变为可写。
pgaccess 的输出校验也接受逻辑可写的 COW 页，但仍拒绝未映射或真正只读的输出。

## 持锁期间的内核栈缺页

内核栈默认预留 2 MiB，初始提交 32 KiB。创建栈时预先建立覆盖整个容量的叶页表，
再发布槽位；每个 2 MiB 段需要一张 4 KiB 叶表。实际补页不用再分配页表。

每 hart 有 16 KiB 应急入口栈，以及 64 个预先分配的应急物理页（256 KiB）。
应急页在启用调度前准备，并仅在未持有自旋锁的内核异常入口补充。
进入异常时中断关闭；`noff` 非零时，补页完全从当前 hart 的应急池取页，
不取得物理分配器锁、区域锁或调度锁。处理器直接使用当前栈所有者的稳定范围、
槽位发布标记和预建叶表，不遍历可能正被锁保护修改的区域元数据。

普通无锁缺页可先使用物理分配器，失败时使用应急页。普通中断尝试补齐下方
32 KiB 余量，内存不足时允许跳过；实际缺页必须取得所需页才能返回重试。
只对不存在的 PTE 建立 RW、不可执行、仅内核可访问的映射，结束时刷新本核 TLB。

这消除了补页递归取得栈管理锁或物理分配器锁的路径，但不是无限的持锁栈容量承诺。
一次无法补充应急池的临界区若耗尽 64 个应急页，会明确 panic；保护区及权限错误也直接 panic，
不会无限重试或自旋等待自己的锁。新增大递归和巨型局部对象仍须控制临界区资源预算。
回收栈必须等所属进程停止运行并完成锁交接，随后归还提交页、叶表和区域记录。
内核页表统计也持区域锁保护页表节点生命周期；无锁补页可以并发添加叶子，因此数量是观测值，
不能当作全局瞬时快照。叶子发布和统计读取使用原子访问。

## 写时复制 fork

fork 复制页表和区域元数据，共享用户数据帧。原可写用户页在父子两侧清除 W 并设置
软件 `PTE_COW`（RSW bit 8）；真正只读页保持只读，不设置 COW。
写缺页只有在区域允许写入且 PTE 为只读 COW 时才处理：

- 仍被多个映射持有：分配并复制 4 KiB，替换当前 PTE 后释放旧引用。
- 已经只剩当前所有者：原地恢复 W，清除 COW，无需额外物理页。
- 分配失败：保留原 PTE、权限与引用计数，向调用者返回 OutOfMemory。

共享引用使用 RAM 元数据区中的每帧 32 位原子计数；从未共享的帧隐含一个所有者，
首次共享转换为两个引用。用户 4 KiB 叶子取消映射时通过 release_page 归还引用，
最后一个引用才回到物理空闲链表。页表、内核栈及未拆分的高阶分配仍按原独占所有权释放。
该数组使 buddy 元数据从每 RAM 页 4 字节增加到约 8 字节，freelist 从约 1 字节增加到约 5 字节，
另有对齐和页面取整开销。

原有 2 MiB 用户大页在第一次 fork 时拆成 4 KiB 叶子和独立物理页所有权，再执行共享，
避免一个 4 KiB 写入复制整块 2 MiB。未经过 fork 的大页分配、整块释放及部分缩小继续支持。
fork 失败会回收候选子映射；父表已经变为 COW 的部分可以保留，之后独占提升即可恢复写权限。

当前每进程一个执行线程，不共享用户页表。修改父 PTE 后刷新本核翻译，后续用户返回也会刷新；
跨进程共享的是数据帧，计数原子化。未来若增加共享地址空间线程，需要补充地址空间锁和远程 TLB shootdown。

## 验证

- vm_buddy_contract / vm_freelist_contract：实际 VM/分配器代码上的区域冲突、分裂、复制、
  引用并发、只读/保护/越界故障、COW/copyout、OOM 不修改原映射，以及全部资源回收。
- vm_stack_contract：使用真实编译数据库构建私有诊断 ELF，验证持自旋锁时约 196 KiB 栈增长，
  应急池从 64 页降到 22 页，以及已映射只读栈页、应急池耗尽和保护区的明确失败。
  诊断代码由 XV_VM_SELF_TEST 控制，正常内核为零，不执行探针；不会改动正常 ELF 或源文件。
- vmcheck：真实客体上的 24 MiB fork 共享、父子及孙进程隔离、管道 read 的内核 copyout、
  懒分配、只读文本/PID 页/NX/越界、pgaccess 的 COW 输出，以及统计期间并发 fork/栈表回收。
- superpgfork：保留初始大页检查，fork 后检查 4 KiB COW，并验证子写入不影响父内容。
- 完整 usertests、单核/五核功能与网络回归，以及不同 RAM 配置的启动测试。

测试镜像来自新构建的 fs-test.img，不修改用户正在运行的持久 rootfs。
普通构建只更新安装种子，内核功能在加载新内核后生效；现有 rootfs 的用户程序可通过
离线 rootfs-update 安装，见 [rootfs 工具](rootfs-tools.md)。
