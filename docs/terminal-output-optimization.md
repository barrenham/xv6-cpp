# 串口镜像与批量输出优化

串口镜像是把PTY内命令输出复制两份：一份绘制到VNC画面，一份写到启动QEMU
的串口终端。因此原SSH/串口窗口也会显示命令及其结果。

本轮保持普通 `fbterm` 的双端显示，优化非阻塞TTY发送，并增加可选开关：

```sh
fbterm --no-serial-mirror
fbterm --no-serial-mirror cat /usr/share/doc/xv6/README
```

关闭镜像后，命令输出和内层shell回显只在屏幕中显示，VNC键盘和串口输入都
保留。连接/退出提示仍写到串口；保持原SSH/串口连接打开，Ctrl-]仍可退出。
本轮没有改变刷新间隔、字体、GPU协议或默认分辨率。

## 内核修改

TTY非阻塞写入由逐源字节发送改为先尝试至多32源字节。TerminalOutput的
全块接受契约保持：发送成功才增加源字节进度；EAGAIN时经WriteFlow的
Retry/Shrink节点将源前缀向上取半，重新转换并发送，最迟缩至1字节。

缩小前缀不重新从用户空间取数据，不改变已完成进度，不把ONLCR展开后的
输出字节数作为write返回值。一个源换行产生的完整CRLF仍作为同一块提交，
最小块也无法接受时返回已有进度或EAGAIN。其他后端错误不触发缩小重试，
原有信号检查、写者锁、输出标志快照和阻塞路径保持。

这减少了逐字节用户数据复制、后端锁及通知开销。默认镜像仍有背压：如果
需要图形输出与串口速度无关，应使用显式关闭镜像的选项。本轮没有引入
无限队列或丢弃串口数据的策略。

## 相同负载复测

2026-11-01，1920×1080，五核，本地500行文件，经PTY输出22013字节；每组
两轮，反转模式顺序；测试依次运行，不同时运行其他测试。基线为
[优化前排查](display-performance.md)。

| 模式 | 优化前传输循环中位数 | 本轮中位数 |
| --- | ---: | ---: |
| 默认镜像、无VNC | 22.58s | 4.21s |
| 关闭镜像、保留完整绘制、无VNC | 1.32s | 1.06s |

默认镜像本轮两次分别5.21s和3.21s，存在调度波动；中位改善约5.36倍。
相同范围内的串口write阶段中位数从20.41s降至2.31s。完整命令的宿主墙钟
中位数（包含启动、初始清屏、诊断报告等）从23.82s降至5.46s。

另用真正的 `--no-serial-mirror` 命令行开关接入持续读屏的本地Raw VNC
客户端，两轮传输循环为1.30s、1.01s，中位1.15s；镜像字节计数均为0，
解析字节数均为22013，客户端实际接收画面更新。此数据不能等同于远程
MobaXterm的网络条件，时间也不是线程纯CPU时间。

## 验证和安装

- nonblock_1cpu、nonblock_5cpu：增加10种剩余队列空间窗口，检查批量短写、
  源字节计数、CRLF完整性及重试后无重复/丢失；原有EAGAIN、信号和标志检查保留。
- pty_1cpu、pty_5cpu：PTY数据、背压、关闭及终端语义回归。
- fbterm_contract、fbterm_1cpu、fbterm_5cpu、keyboard_1cpu、keyboard_5cpu：
  字体/渲染契约、2000行完整输出、实际GPU画面、VNC键盘、关闭镜像后的
  串口输入和仅屏幕输出、EOF/分离及标志恢复。
- 新的镜像关闭与快速输出测试按有时限的实际屏幕条件等待，处理异步合帧；
  未减少工作量或修改已有fork门禁参数。初次固定400ms截图出现的过早断言
  保留在诊断日志，后续通过实际画面条件复测。
- kernel函数清点、文档覆盖、控制流绑定检查通过：404文件、5230文档条目、
  227个既有非网络控制图；新Retry/Shrink属于原WriteFlow。生成索引已更新。
- fork性能门禁继续按用户要求跳过。

安装使用离线rootfs更新工具，保留精确备份，核对/bin/fbterm、
/usr/tests/ptytest与构建结果一致，并比较/etc、/home、/root、/data内容和
所有者/权限。内核改动随构建产物生效；安装完成后重启QEMU使用新版。
