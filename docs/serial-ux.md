# 串口交互与增量绘制

本次优化针对 serial 的 ANSI 字符流。Shell 不再在方向键、退格或历史浏览时清除光标以下区域并重发完整提示符与输入；Vim 不再每次按键重发全部可见行。

Shell 的 `LineDisplay` 保存上一版输入、逻辑光标位置、物理行和末列待换行状态。比较共同前缀与等长文本的共同后缀，只输出变化的范围；删除多余字符时仅用空格覆盖旧输入。提示符的账户查询、getcwd 与配色检测移到每次开始读命令时执行，按键重绘使用缓存。

追加输入在输入队列暂时为空或累计消费 128 字节时合并回显。读取仍是一字节一次，Enter 后的数据留给下一程序。后台任务通知先隐藏光标、擦除本次输入占用的单元，再显示通知并恢复提示符、草稿和光标。未使用全屏或光标以下区域清除来重建输入。

Vim 保存最多 100×240 个字符及每行显示状态，首次显示、尺寸变化时重新绘制；普通编辑只更新变化的字符和缩短行的旧尾部。行宽刚好占满时避免额外清行擦掉末列字符。

## 验证与边界

`serial_line_contract` 对 8、12、80 列执行 12000 次编辑与光标移动，逐格校验文字、光标及待换行状态，并验证擦除范围不覆盖下方无关内容。`serial_ux_1cpu/5cpu` 检查长行移动、末列插入、后台通知草稿恢复、输入交接与关机后的文件系统一致性。`vim_1cpu/5cpu` 使用 ANSI 屏幕模型校验增量显示，并验证保存内容与 termios 恢复。

串口客户端负责最终字形绘制与滚屏。这里消除的是应用主动反复清除和重发画面的开销，不保证任何客户端、链路速度或任意输出量下都没有视觉停顿。Shell/Vim 仍按字节处理 ASCII，未加入 UTF-8 宽度支持。串口输入缓冲有限，压力测试分批发送输入，不将任意突发灌入视为无损传输保证。

## 2026-11-08 实测

五核 QEMU、相同内核与独立根盘副本，对同一条 300 字符命令连续向左移动 50 次。旧 Shell 使用优化前保存的 ELF，新 Shell 使用当前构建产物；逐次确认光标定位，避免输入缓冲溢出干扰比较。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 串口输出 | 16,800 字节 | 300 字节 |
| CSI J 清除光标以下区域 | 50 次 | 0 次 |
| 本次交互耗时 | 3.2644 秒 | 0.5065 秒 |

输出减少 98.21%。耗时包含测试驱动与主机调度，仅代表本次条件下的采样。Vim 打开三行文本后向右移动一次，输出 35 字节，仅定位、更新状态栏列号及控制光标显示，没有重发正文。

最终 15 项原生与单核/五核客户机检查全部通过；首轮两个新增长输入测试发生回显超时，保留原日志，重建测试镜像并改为逐批确认回显后复测通过。持久根盘更新 `/bin/sh`、`/bin/vim` 两个文件，149 个可替换 manifest 文件与构建内容和元数据一致，账户及服务配置与安装前备份一致，只读 e2fsck 通过。重启 QEMU 使用新版。
