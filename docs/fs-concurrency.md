# 用户态 FS 的并发与缓存

内核桥接在 V2 批量传输上协商三个独立 `SOCK_SEQPACKET` 通道。通道 0
处理元数据，通道 1、2 分别拥有请求、回复和共享内存切片，处理普通文件数据。
同一 inode 使用睡眠式读写锁：独立打开同一普通文件的读操作可以同时持有
共享锁，写入、截断、属性及映射释放持独占锁。不同普通文件
不再持有整个 FS 实例的元数据锁等待数据回复。带 set-id 位文件的写入仍保留
元数据事务，确保清除权限位与写入的顺序正确。

每个打开文件对象另有睡眠互斥锁保护偏移，覆盖 read、write、lseek 和
getdents64；fork/dup 共享该对象，也共享此锁。因此同一打开文件对象上的读取
仍按顺序推进偏移，分别 open 得到的对象则允许并发读取相同 inode。
锁顺序为打开文件偏移锁、FS 元数据锁、inode 数据锁；普通读取取得共享数据锁后
立即释放元数据锁。目录读取保留原有独占保护。读取与文件缺页在共享数据锁下
取得缓存页租约；缓存元数据由短暂自旋锁保护，RPC 和用户拷贝期间不持该锁。
不同页可以并行加载，逐页加载中的同页重复缺失睡眠等待同一结果；映射租约使用
原子发布避免重复计数。写入、截断和映射释放仍持独占数据锁。

读写锁等待时登记通道并挂起进程，不忙等；内部短暂自旋锁只保护锁状态。
写者排队后，新读者也等待，现有读者全部退出才能交给写者；不承诺严格 FIFO。
共享映射的用户态直接存取不会取得此锁，应用仍须自行同步。

SDK 统一使用固定 pthread 工作池，不再提供进程池或 fork 快照读模式。
ramfs 的数据回调使用命名空间共享锁和 inode 条带读写锁；其他后端先用整卷/整后端
独占锁保护缓存和事务。`workers=1/2` 仅调整线程数量。请求身份放在静态 TLS；
命名空间、Forget、snapshot 和维护为全局屏障。详见[统一 FS 线程池](fs-persistent-workers.md)。
通道允许多个内核请求同时等待；独立 ELF 可以并行处理并逆序回复。内核不会
要求插件的处理函数可重入。旧 V1 批量传输和旧字符设备请求协议继续工作。

## 缓存契约

V2 的 `cache_flags` 为后端主动声明的一致性能力，默认 0。ramfs、ext3、xv6
声明 `CacheMetadata`，要求该挂载实例的文件与属性修改均通过桥接执行。
proc、devfs 等动态后端不声明该标志。没有引入未经插件声明的自动缓存。

每实例有至多 12 条 LRU 正路径缓存，并复用已经取得的 inode 属性。缓存持有
父目录及目标 inode 引用；淘汰时释放引用，最后一个引用按原协议发送 Forget。
不缓存 `.`、`..` 或失败查找。可用 inode 槽不足时先清理缓存再进行查找。

创建、删除、重命名、硬链接、权限修改和普通插件控制请求会清理路径缓存并
使属性失效；写入和截断更新大小，失败的变更使相关属性失效。后端断开后
不能继续使用缓存查询。卸载检查先释放缓存引用，避免缓存让挂载永久繁忙。
普通文件内容缓存与 mmap 共用物理页；每 inode 的闲置缓存上限为 8 页，
`read_hits` 统计就绪缓存页命中。普通写入采用写穿。

## 运行验证

2026-11-07 的睡眠式读写锁变更通过 `sync_contract`，覆盖实际睡眠、共享读者、
写者排队和混合竞争。`build/sleep-rwlock-final-validation.log` 记录最终 11/11
回归通过，耗时 343.17 秒，包含单核/五核 FS 并发与文件映射、ext3/xv6 部分写入、
路径 socket、POSIX IPC、五核驱动启动及 FS/进程原生契约。

- `fs_concurrency_1cpu`、`fs_concurrency_5cpu`：测试后端必须同时收到两次不同
  文件读取、两次同一 inode 的独立读取才回复，且逆序返回；校验各自共享内存内容、
  请求 ID 与断开后的双等待者唤醒。统计要求 `maximum_in_flight=2`，结束后 `in_flight=0`。
  在 ramfs/ext3 上同时检查 fork/dup 共享偏移逐字节读取不重复、不遗漏。
- 同一测试中的 `fscachetest`：ramfs、ext3 上 96 次重复路径/属性操作新增
  RPC 为 0；覆盖重命名、替换后仍打开的 inode、硬链接、删除、权限变化和淘汰。
- `tools/profile_fs_concurrency.py`：私有根盘固定 64 次操作，分别测 1/4 个进程，
  包含元数据、同文件读、不同文件读、不同文件写。fork/barrier 建立不计入用时。

2026-11-05 的五核 QEMU 单次测量，四进程元数据阶段：

| 后端 | 优化前 RPC | 优化后 RPC | 优化前耗时 | 优化后耗时 |
| --- | ---: | ---: | ---: | ---: |
| ramfs | 192 | 0 | 482.7 ms | 98.7 ms |
| ext3 | 320 | 0 | 676.7 ms | 91.1 ms |

不同文件写入阶段 ramfs 从 217.5 ms 到 136.8 ms，ext3 从 3879.6 ms 到
3581.6 ms。同文件读及不同文件读在这次测量中更慢：独立通道和多路轮询对小
请求增加开销，不能将元数据改善等同于所有 I/O 都更快。这些是诊断数据，
不是性能门禁，也不包含宿主机噪声的统计置信度。

原始结果在 `build/fs-concurrency-before.json`、`build/fs-concurrency-after.json`；
缓存/并发功能结果在 `build/fs-cache-first-tests.log`，9/9 兼容回归在
`build/fs-cache-regression.log`；最终新增的断开和同步失败失效检查见
`build/mapping-cache-final-validation.log`（6/6）。
