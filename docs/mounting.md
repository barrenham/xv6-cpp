# 动态 RAM 挂载

```sh
mount
mkdir /tmp/work
mount -t ramfs /tmp/work
echo hello > /tmp/work/file
cat /tmp/work/file
umount /tmp/work
```

`mount` 无参数列出挂载类型和路径，普通用户也可以查看。新增挂载和卸载仅允许有效 UID 为 0 的进程执行。当前支持类型为 `ramfs` 的独立内存文件系统，挂载点必须是已有目录，使用规范绝对路径，不含重复斜杠、`.`、`..` 或结尾斜杠。挂载根为 root:root 0755，需要开放给其他用户时可再 chmod/chown。

全局挂载表最多 8 项：启动时固定的 `/dev`、`/proc`、`/tmp`，最多 4 个动态 RAM 实例，以及一个持久磁盘实例。固定挂载受保护，不能卸载。没有挂载命名空间、bind mount、磁盘分区发现或延迟卸载；不能在一个已经挂载的根上继续叠加挂载。

挂载覆盖目录原有内容，不删除原内容；卸载后底层内容重新可见。动态 RAM 中的文件在卸载时全部丢弃，不写入磁盘。支持在动态 RAM 中建立子挂载，需要先卸载子挂载。

## 生命周期与并发

VFS 使用命名空间 SleepLock，路径遍历取得稳定 inode 引用后才释放它；create/link/unlink/rename 和挂载表修改使用相同锁。锁内按后端执行节点操作，不在持自旋锁期间等待目录 I/O。路径系统调用先取得日志事务，再进入命名空间锁，保持锁顺序一致。首个进程在调度之前直接取得磁盘根引用，避免提前使用需要进程上下文的睡眠锁。

每个动态实例有独立的树锁、引用锁、编号位图和节点链表。外部引用总数不计目录指向父节点的内部固定引用；根的初始化引用及挂载表引用共两个。打开文件、cwd、未删除路径查找引用、已删除但仍被持有的目录，以及子挂载的覆盖点/父节点引用都会使实例忙碌。只在外部引用回到根的两个固定引用时才允许卸载。

卸载期间命名空间锁阻止新路径进入，树锁等待已完成引用扣减但仍在回收的操作退出。随后遍历节点链表销毁全部数据页、目录页和节点页，清空位图并释放实例槽。分配挂载根失败时返回错误，释放预先取得的覆盖点和父节点引用，不发布半成品挂载。

`mount_info` 共享结构包含 path[128] 和 type[32]。`mountinfo(index, &info)` 返回 1 表示一条记录，0 表示枚举结束，-1 表示参数或复制错误；并发挂载变化时逐条枚举不保证整表快照。`mount(type, path)` 与 `umount(path)` 返回 0/-1。

workflow 测试检查覆盖内容、打开文件/cwd/子挂载阻止卸载、权限、重复使用槽位和 mount 祖先保护。宿主机 fs_contract 还注入根分配失败、持有已删除目录，并逐轮核对卸载后全部页面回到基线。

## 持久 rootfs

默认 QEMU 使用工作区 `data/rootfs.img` 作为第一个 VirtIO 块设备。它直接成为 `/`，
包含 `/bin`、`/sbin`、`/usr`、`/etc`、`/root` 和 `/home`；`/dev`、`/proc`、`/tmp`
仍由 devfs、procfs、ramfs 覆盖。`mount` 的首项显示根文件系统，根卷不可卸载。

`rootfs-image` 目标仅在目标不存在时，从构建产物 fs.img 复制完整安装种子。
默认创建不带既有账户的干净根盘；旧 data/data.img 只有显式配置导入时才迁移，原镜像始终保留。新镜像经完整构建后
以不覆盖已有文件的原子方式发布；失败不会留下半成品。已有 rootfs 不会被构建或重启覆盖。
普通构建只更新种子；退出 QEMU 后可运行 rootfs-update，备份并原子更新根盘中的清单程序，账户与用户目录保留。
生成自己的全新根盘使用 rootfs-create，已有目标会报错。详见 [rootfs 工具](rootfs-tools.md)。
配置项、迁移边界和切换全新开发镜像的方法见 [开发说明](development.md)。

## 可选辅助磁盘

默认启动不再连接第二块磁盘。手动连接第二个 VirtIO 块设备时，可把已有 xv6 文件系统
显式挂载到 `/data` 或其他目录，账户和 HOME 始终使用根卷中的路径。

```sh
mount -t xv6 /data
ls /data
umount /data
```

只支持这个已连接的辅助卷，不支持任意设备路径、分区或格式化命令。同一卷不能同时挂载两次。
打开文件、cwd、子挂载等引用会阻止卸载。卸载只释放挂载引用并落盘，不销毁文件内容。
可用 `tools/create_data_image.py --mkfs build/dev/mkfs --output /path/aux.img` 创建独立空辅助卷；
该工具也不会覆盖已有文件。

根盘与辅助盘分别有 VirtIO 队列、块缓存、inode 缓存和日志。路径事务按根盘→辅助盘
的固定顺序预留日志，提交顺序相反，不构成跨卷原子事务；rename 继续拒绝跨后端。
日志提交、fsync/sync 与 VirtIO FLUSH 的行为保持不变。新安装种子默认 16 MiB；
创建 rootfs 不会自动扩大现有卷。

persistence 单核/五核测试验证 rootfs 重启后保持账户、密码和文件，以及种子变化不会覆盖根盘；
同时检查辅助卷挂载不改变 HOME，旧卷迁移后权限、链接和密码仍有效，原卷字节不变。
