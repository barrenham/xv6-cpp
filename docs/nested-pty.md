# fbterm 内嵌套 PTY 的换行和退出键

在fbterm中启动pty，或者连续嵌套多层pty时，每次Ctrl-]只结束当前最内层
代理；等待返回上层提示符后，再按Ctrl-]继续向外退出。VNC键盘和串口输入
使用相同规则。只有退出最后一层fbterm时才返回外面的串口shell。

## 换行

pty原先在外层TTY进入raw转发后，仍给新子PTY使用默认输出设置。fbterm依赖
OPOST/ONLCR将换行变成CRLF；外层raw关闭转换、内层也没启用ONLCR，导致LF
只向下移动而不回到行首，提示符连续向右偏移。

新子PTY只继承父端保存的c_oflag，保留各终端原本的输出处理行为；其他行
规程设置和控制字符继续使用新PTY默认值。图形模式在最内层转换一次CRLF，
中间各代理raw转发不重复转换；普通串口模式保留原有LF行为。连接提示在
父TTY已经raw时按保存的输出模式选择LF或CRLF，退出提示在恢复原模式后输出。

## 退出键归属

私有termios标志XV_PROXY（0x80000000U）声明当前TTY上有前台输入代理。
pty与fbterm设置父端raw模式时同时设置该位，退出时恢复完整保存的termios。
子PTY仍使用独立初始模式，不继承代理声明。

共享的user/runtime/terminal_proxy.h在收到Ctrl-]时，通过子PTY主端TCGETS
查询该位：有内层代理则继续转发；否则当前代理分离。查询失败时允许当前
代理退出，避免无法分离。标志只用于协作，不提供权限，也不改变内核字符
处理、信号或窗口尺寸。它是xv6扩展，不属于Linux/POSIX标准标志。

此方案不靠程序名、TERM、提示符内容或raw模式猜测层数。普通raw前台任务
没有设置代理声明，因此保持既有的Ctrl-]分离行为；每层独立恢复原模式，
避免退出内层时一起关闭fbterm。它也不把一批中其他字节重复提交。
