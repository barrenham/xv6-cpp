# 截止时间队列与网络超时任务

本次改动针对 v0.0.3 的定时中断调用链：每个 hart 每 100ms 中断一次，hart 0 在中断中执行 poll 等待链表扫描、TTY 服务和整个网络 TimerFlow。网络 TimerFlow 顺序处理接口、IPv4 分片、DHCP、全部 socket、再处理接口。TCP 重传、零窗口探测、TIME_WAIT 回收和 loopback 递送都在这条调用链上。

这种安排有两个独立问题。到期时间只能在下一次周期扫描时被发现，短等待因此受到近 100ms 的量化影响；协议的报文构造、发送、遍历与内存回收又拉长中断处理。单纯把周期改成 1ms，会把空扫描次数增加约 100 倍，也会错误改变按 tick 计量的 uptime、pause 和调度量子。

## 统一队列

`kernel/support/deadline_queue.h` 使用现有侵入式红黑树组织绝对毫秒截止时间。同一时间用节点地址作稳定的第二排序键。登记和重设调用 reset：先撤下旧节点，再按新时间插入；取消调用 cancel，已取消节点重复取消无副作用。同一节点最多属于一个队列，跨队列使用前须在原队列取消；取消不撤回已经投递给进程的触发状态。插入、重设和删除为 O(log n)，无需按等待者数量预分配数组，也不为每个定时器分配内存。

WaitChannels 持有一把队列锁；PollWait 把节点嵌在自己的对象中。expire 只检查最早节点，每次最多发出 64 个通知。节点先移除再通知，通知只设置触发状态并让进程可运行。通知在队列锁内完成，因此取消与析构返回时，不会留下访问已释放 PollWait 的回调。通知不得分配、睡眠、运行协议或重新进入队列。剩余已到期节点由下一次至少间隔 1ms 的中断继续处理。

用户 poll、设备完成等待以及网络任务的下一次唤醒共用这一队列。PollWait 增加显式 cancel_deadline，set_deadline 允许重设。原来按 tick 表达的 pause 和 TTY 周期服务仍保留 100ms 语义。

## 网络工作任务

启动时先创建 PID 1，再创建永久的 `net-timers` 内核任务。任务使用正常的进程内核栈、上下文和就绪队列；第一轮调度释放进程锁后进入内核入口，不进入用户态。任务不接受 kill 或用户信号，不参与用户进程组，任务入口返回会报内核错误。当前实现借用完整进程描述符及其空用户地址空间，尚未为内核任务单独精简这部分开销。

任务在可调度上下文调用原有网络 TimerFlow。TCP 的 registry 锁改为逐槽获取，指针仅在持锁期间使用，socket 的关闭、销毁和复用不能把悬空指针留给后台任务；释放一个槽的锁后可以响应中断和调度。单个 socket 的协议状态转换仍由原有锁串行保护，持有自旋锁的短区间仍不能被抢占。

每轮结束后，在各自所有者锁内查询 TCP RTO/persist/停滞/FIN_WAIT_2/TIME_WAIT、本地输出失败重试、ARP 待发送包、IPv4 重组、DHCP 重试/租约和网桥 FDB 的最早截止时间；loopback 有队列时报告立即工作。没有网络工作时，任务无限期睡眠，不再每 100ms 空扫 socket。这里使用一个聚合的网络任务截止时间；仍会在网络状态变化或到期时扫描现有固定容量表，并没有为每条连接单独建立树节点。

IPv4、ARP、TCP、DHCP、loopback 和网桥接收/管理路径在状态发布后通知任务。generation 计数合并重复通知。任务先永久订阅通知通道，再读取 generation、执行工作、查询截止时间，最后重新比较 generation。计算期间有变化则继续一轮；比较以后有变化则订阅触发状态阻止睡眠，避免“检查完毕才收到通知却一直睡下去”。连续八轮后主动让出 CPU，正常定时抢占也继续工作。订阅页在任务启动时分配一次并长期复用。

本地发送失败重试需要特别处理：旧扫描虽然没有专门标记，也会每 100ms 再次 pump。事件驱动后若只登记已发送数据的 RTO，尚未成功发送的数据可能一直等到停滞超时。因此为仍有发送额度但本地输出失败/路由暂不可用的连接保留显式 100ms 重试截止时间。

## 多核等待对象的地址有效性

压力测量发现一个原先较难触发的 TLB 问题。等待节点位于可回收的进程内核栈虚拟窗口；栈地址被下一个进程复用后，另一个空闲 hart 可能仍缓存旧的物理页映射。调度器切换前后的 sfence 只保护实际参与切换的 hart，不能保护空闲 hart 在定时中断中沿共享等待指针读取别人的栈。

GDB 在异常现场观察到当前页表下节点的左右指针均为零，而出错 hart 已把 0x0101010101010101 读入寄存器；物理页写观察点也确认这个数来自先前栈页的释放填充。这证明不能只依赖对象锁来保证翻译有效。修复是在队列非空时、持队列锁访问节点前执行本地 sfence.vma；订阅 bucket 持锁访问 PollWait 所有者前也执行刷新。锁保护对象生命期，刷新保护当前映射，两者职责不同。这里采用保守的全本地 TLB 刷新，其成本计入后续实测。队列额外缓存最早截止时间的数值，周期检查尚未到期时不访问节点，也不刷新 TLB；未来仍可按栈映射代次减少实际操作节点时的重复刷新。

## 硬件唤醒

周期调度节拍保持 100ms。TickClock 为每个 hart 保存下一周期边界，只有跨过该边界才推进全局 uptime 或向调度策略报告一次 tick。短超时中断不会把 pause、CPU 时间采样或调度量子变成 1ms。总中断计数仍包含这些新增中断。

登记等待时，在登记操作所在 hart 上把 stimecmp 提前至队列首截止时间；中断结束时也取周期边界与最早截止时间的较早者。跨 hart 无需直接写远端 CSR：登记者自己保证至少有一个 hart 会在新截止时间到来时醒来，其他 hart 的旧比较值允许产生一次无害的多余中断。到期队列仍由共享锁保护，只能投递一次。

已经到期的工作和网络状态通知使用至少 1ms 间隔的一次性唤醒；不会把所有 CPU 改为固定 1kHz 时钟。短超时中断提供一次调度机会，无需等待公平调度策略的旧时间片耗尽。poll 的截止时间向上取整，避免毫秒截断导致早于请求时长返回。1ms 是设计的最小硬件间隔，并非对负载下端到端唤醒延迟的实时保证；关中断区间、就绪队列和宿主机调度仍影响实际延迟。

## 验证与复现

随机模型验证十万次登记、重设、取消、同时间节点、到期预算与一次性通知；进程等待契约覆盖重设、显式取消、通知与析构并发。真实 QEMU 使用私有磁盘副本验证启动、poll 和网络通信，保留用户持久镜像。

`user/tests/timerbench.cpp` 使用 rdtime 系统调用测量 poll 的实际耗时。`tools/profile_timers.py` 对改动前后内核运行相同测试程序，每种 1/5/10/25/100ms 等待各 20 次，样本先存内存、计时批次结束后才统一打印，并记录三秒空闲区间与整批测试的 QEMU 进程 CPU 时间。该 CPU 指标是宿主机累计 user+system 时间，包含所有 vCPU 和模拟设备线程，不等同于某一段内核函数独占的 CPU 时间。测试关闭图形显示，串口输出和登录过程不计入空闲区间。

实测原始样本、二进制 SHA256 与限制保存在 [验收数据](deadline-timers-acceptance.json)。同一测试镜像运行改动前 v0.0.3 内核与当前内核，1/5 核各两轮，每项合计 40 个样本；下表是耗时中位数，不是额外延迟：

| 请求等待 | 原先 1 核 | 当前 1 核 | 原先 5 核 | 当前 5 核 |
| --- | --- | --- | --- | --- |
| 1ms | 100.73ms | 2.68ms | 100.88ms | 2.81ms |
| 5ms | 100.78ms | 6.95ms | 100.68ms | 6.90ms |
| 10ms | 101.22ms | 11.91ms | 100.74ms | 12.03ms |
| 25ms | 101.08ms | 26.93ms | 100.93ms | 27.45ms |
| 100ms | 103.35ms | 102.43ms | 101.50ms | 103.45ms |

1ms 请求的 P95：原先约 102–103ms，当前约 4ms。原先 100ms 请求的 P95 约 202ms，当前约 105–106ms；因此收益也包括减少跨过一次扫描边界带来的长尾。当前仍有系统调用、锁、中断和调度开销，1ms 硬件间隔没有变成 1ms 的实时调度保证。

100 次等待组成的整批测试：单核 QEMU CPU 时间由 0.31/0.33 秒变为 0.34/0.31 秒；五核由 0.69/0.61 秒变为 0.54/0.58 秒。三秒空闲等待：单核由 0.06/0.06 秒变为 0.05/0.06 秒，五核由 0.16/0.13 秒变为 0.16/0.19 秒。CPU 采样分辨率为 10ms，两轮数量有限，不能把这些差异解释成所有网络负载都获得相同比例的 CPU 改善。短等待的整批墙钟耗时显著缩短，CPU 总时间与 CPU 占墙钟时间的比例也应区分。

用户的开发 QEMU 保持运行；性能测量时没有同时启动本轮其他回归客体或编译。第一次带样本逐行输出的测量暴露了 TLB 异常，已排除出正式数据。修复后还增加了最早时间缓存，正式数据只使用该版本。

相关回归包括启动、进程/信号/调度、poll/非阻塞、TCP/UDP、DHCP、DNS、HTTP、网桥、网络管理、两种物理分配器的 VM 契约，共 34 项通过。最早时间缓存落地后补跑其直接影响的等待、启动、信号与网络测试，原生随机容器另通过 ASan/UBSan/泄漏检查。fork 性能门禁未运行。
