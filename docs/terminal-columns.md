# ps/free 列布局与 Tab 验证

ps 原先用一个空格分隔各个数字，列位置会随 PID、父 PID 和内存值的位数变化；它并没有用 Tab 排列表格。free 的数字也使用同样的单空格方式。这个问题发生在输出生成端，所以串口终端和 fbterm 都会显示错列。

用户态 printf 现在支持十进制最小字段宽度、左对齐和零填充，例如 `%6d`、`%-5s`、`%8lu` 与 `%05d`。宽度只补齐，不截断超长数值；负号、64 位数及原有 `%d/%u/%x/%p/%c/%s/%%` 保留。没有加入动态宽度或精度等完整 libc 格式集合。

ps 对四个进程 ID 使用 6 列右对齐，状态使用 5 列左对齐，KiB 使用 8 列右对齐，名称从同一列开始。free 使用 10 列的数值字段。头部与数据使用相同布局；实际值超过最小宽度时仍完整输出，不用截断隐藏信息。

Tab 是把光标移动到下一个停靠点，不是始终插入固定数量的空格。fbterm 原有默认停靠点位于第 8、16、24 等列；例如 `processor\t: ` 与 `hart\t\t: ` 都把冒号放到从零计数的第 16 列。用户态 printf 原样发送真正的 Tab 字节，TTY 不把它变成字母 t 或反斜杠文字。仅输入字面量 `\\t` 是否转换，取决于命令自身和 shell 的转义规则。

验证分三层：printf 原生契约检查对齐、零填充、负数、64 位边界、字符串及真实 Tab；终端单元契约检查不同起点、连续 Tab 和行尾；真实 QEMU 检查串口的 ps 列位置，并通过 GPU 截屏按字体逐字符解码，确认 ps/free 列位置及 cpuinfo 的冒号在第 16 列。显示路径没有靠缩放字形修饰对齐。
