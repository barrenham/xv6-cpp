# memory 模块的 slab 对象分配

`import xv.memory;` 导出 `SlabCache`、`FreeListSlabCache`、`BitmapSlabCache` 和通用对象服务。
物理页仍由 `PhysicalPageAllocator` 管理；slab 将一页分成多个固定尺寸对象。
本次接入 `Session`、`ProcessGroup`、进程描述符和 `VirtualAddressPool` 的区间节点。
前两类使用尺寸类服务，后两类使用共享的精确尺寸缓存；地址空间不再各自支付一整页元数据成本。
页表、用户帧、内核栈数据页和需要整页地址对齐的对象继续使用物理页分配器。

## 多态与配置

`SlabCache` 提供虚方法 `allocate/deallocate/trim/statistics/name`。
共享实现负责页面所有权、对齐、活跃位图、部分空闲页链表、空页链表和锁；
派生类通过策略虚方法实现槽位准备、分配与归还：

| 实现 | 槽位分配 | 空页初始化 |
| --- | --- | --- |
| `FreeListSlabCache` | 从对象内嵌的空闲索引链表弹出，归还时压回 | 初始化所有空闲索引 |
| `BitmapSlabCache` | 在最多四个 64 位字上取反并使用 ctz 定位 | 清零页头的活跃位图，不逐槽初始化 |

两者都是实际实现，可通过 `SlabCache &` 替换，不依赖 RTTI 或全局堆。
分配槽位不扫描所有对象，满页不在可分配页链表中。

默认 `XV_SLAB_ALLOCATOR=freelist`，另一个内核配置为：

```sh
cmake --preset slab-bitmap
cmake --build --preset slab-bitmap
```

也可在自定义构建目录设置 `-DXV_SLAB_ALLOCATOR=bitmap`。
它与 `XV_PAGE_ALLOCATOR=buddy/freelist` 独立；宿主契约覆盖两种底层页分配器与两种 slab。
只为选中的生产实现静态创建八个尺寸类控制对象，不在启动时预分配 slab 物理页。

## 对象服务

`allocate_object(bytes, alignment)` 提供 16、32、64、128、256、512、1024、2048 字节尺寸类。
请求尺寸和对齐共同决定尺寸类；支持不超过 2048 的二次幂对齐。
零尺寸、不合法对齐及超出范围的请求返回空指针，不隐式退回整页分配。
`deallocate_object(pointer)` 从页头识别所属尺寸类，验证归属后归还。

返回的是未初始化原始存储，构造与析构由调用方负责；不能把 slab 对象作为独立物理页映射。
对象存续期间地址稳定，不要求或允许通过全局 `delete` 归还。
生产服务立即归还最后一个对象释放后的空页，保持既有内存回收/泄漏检查的精确页计数。
根会话与进程组的常驻对象让其尺寸类仍能在活跃 slab 内复用槽位。

## 私有缓存与回收

调用者可以实例化任一具体缓存，并在发布给其他线程前调用：

```cpp
cache.initialize(allocator(), sizeof(Object), alignof(Object), 1);
```

最后一个参数是可保留的空页上限，默认 1；设为 0 时立即回收空页。
`trim()` 归还所有空页，不移动或释放活跃对象。缓存没有隐式销毁/映射副作用，
存储生命周期结束前必须释放全部对象并执行 `trim()`；空缓存可继续复用。
单缓存支持 1–2048 字节对象，最小槽步长为 16；对齐默认 16，显式较小对齐至少为 8。
页头与所有槽位都位于同一 4 KiB 页内。
过度对齐会降低每页容量，2048 字节对齐可能每页只有一个对象，不承诺所有尺寸都节省页数。

页头记录所属缓存、链表、活跃位和使用计数，不另外分配描述符页。
最后一项归还时根据空页上限选择保留或立即释放；OOM 不会发布半构造的 slab。
物理页耗尽时，已有 slab 的空槽仍可分配，对象归还及 trim 不需要新物理内存。

## 精确尺寸缓存的接入

进程描述符仍通过原 ProcessStore 生命周期构造、发布、摘链和销毁，
对象地址稳定，专用缓存按实际 Node 大小和对齐初始化，当前一页可容纳两个描述符。
真正的 poll 等待页仍经原物理页适配器申请，未将整页对象误交给 slab。

所有 VirtualAddressPool 的区间节点共享一个精确尺寸缓存；每个池只持有两棵树及窗口状态。
reset 删除自己的节点，slab 的活跃计数保护同页其他地址池的节点；copy/swap 的提交与失败原子性保留。
节点分配/回收直接访问对应缓存，避免逐节点重复查找通用尺寸类。
专用缓存也采用所选的空闲链表或位图实现，不保留空页。

## 并发和调用约束

每个缓存使用一个自旋锁，支持跨核归还；初始化在发布前完成，通用服务的首次初始化用原子状态发布。
当前没有每 CPU magazine、无锁 fast path 或 Linux SLUB 的整套机制。
锁顺序为业务锁 → slab 锁 → 物理页分配器锁，没有反向回调。
适用于可使用现有物理分配器的非睡眠内核上下文，不是持锁栈故障的应急分配器。

归还要求指针位于仍映射的 slab 存储中；错误缓存、内部非槽起点和可检测的重复归还返回 false。
原始指针接口不提供跨地址复用的代际检查，也不能安全探测任意未映射的坏指针。

## 正确性与时间开销测试

```sh
ctest --test-dir build/dev --output-on-failure -R '^slab_' -j2
```

- 两种真实页分配器上的两种 slab：10,000 个对象的对齐、数据隔离、碎片重用、空页上限、精确回收；
  8 线程分配/跨线程归还、首次服务初始化竞争、OOM 后槽位重用和非法归还。
  另创建 1000 个独立地址池，检查共享 slab 下的物理页占用、交错 reset 和复制的所有权隔离。
- 宿主性能门禁：64/256/1800 字节，两种 slab，两种空页策略，每组交替顺序测 7 轮，
  每轮 100,000 次分配/释放；中位耗时必须比直接页分配至少低 10%。
  上限为零的场景保留一个常驻对象，模拟生产的根组/会话；上限为一的场景测短生命周期缓存。
  每组热路径的底层页申请只能为预热的一次，对照组必须执行 700,000 次真实页申请。
- 私有 RISC-V/QEMU 内核：两种 slab 通过同一接口，对照真实页分配器进行五轮、每轮 1024 次操作，
  同样要求至少 10% 时间改善、底层页申请一次，并在释放常驻对象后检查空闲物理页精确恢复。
- `slab-bitmap` 配置验证生产服务确实选择位图实现，另检查启动、单核/五核会话和进程组。
- 原 fork 的 5 秒门槛继续保留，在没有其他测试或构建争用 CPU 时独立运行。

宿主计时与 QEMU 计时分别保存到 `build/dev/slab-*-performance.json` 和 `.log`。
性能门禁使用实际实现的虚调用、锁及统计更新；对照页分配包含其既有整页填充/毒化成本。
这些是明确对象尺寸和复用条件下的微基准，不等同于整个内核吞吐收益或零开销承诺。
测量与验证记录见 `docs/slab-acceptance.json`。
