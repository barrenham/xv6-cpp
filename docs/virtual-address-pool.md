# 统一虚拟地址池

`VirtualAddressPool` 管理 `[begin, end)` 内的空闲与已分配虚拟区间，不创建 PTE，
不分配数据帧。已占用节点同时记录区域类型、R/W/X/U 权限及匿名按需分配策略；
原 `VirtualRegions` 实现已删除，每个地址空间只有一个区间管理实例。
调用方通过 `import xv.memory;` 使用它；所有操作由调用方提供并发排他。

## 红黑树基础

`kernel/support/rb_tree.h` 提供不依赖标准库、异常、RTTI 或堆的侵入式
`xv::support::RbTree<Node, Compare>`。节点继承 `RbLinks<Node>`，生命周期与存储由调用方管理。
接口包含插入、按节点删除、精确查找、lower_bound、首尾、前驱/后继和根指针交换。
重复键插入返回 false；删除要求节点确实属于当前树，节点不能同时使用同一套链接加入多棵树。
节点在树中时不能移动或修改排序键；更新键需先删除再重新插入。

红黑树修复使用迭代算法。节点可选提供 `update()`，从自身和子节点重算子树聚合信息；
聚合值不能依赖颜色。插入、删除与旋转维护聚合值，单次查找与修改为 O(log N)。
树不自动释放节点、不提供锁；区间合法性由上层维护。

`rb_tree_contract` 在每次修改后核对排序、父子链接、根颜色、红节点约束、黑高及子树聚合值，
覆盖四组顺序插入/删除和固定种子的 30000 次随机增删，并与标准容器比对查找及双向遍历。

## 地址池的区间协议

地址池使用两棵按起点排序的红黑树：空闲区间树和已分配区间树。
初始化以一个空闲区间表示整个窗口，不为潜在分配预建节点。
地址允许从 0 开始，终点不超过低半 Sv39 窗口；起止地址及请求长度必须是初始化粒度的整数倍，
粒度为非零二次幂，默认 4 KiB，字节区间契约可显式选择 1。
`reserve(begin, end, permissions, kind, demand)` 在指定地址预留区域，支持地址 0；
重叠、越界、非法权限和带访问权限或 demand 的保护区均被拒绝。

空闲树节点缓存子树最大空闲长度。`allocate(bytes, permissions, kind, demand)` 按地址从低到高
选择首个足够大的区间；自动分配以 0 表示失败，因此跳过地址 0。
`allocate_in` 额外接受地址窗口和对齐约束，内核栈从统一池中的栈窗口申请。
普通 first-fit 通过最大长度聚合跳过不满足条件的子树；附加对齐过滤可能访问多个候选区间，
不承诺任意对齐和碎片分布下都为 O(log N)。树递归深度受红黑树高度约束。

`find(address)` 在已占用树中按包含关系查询，返回区间及其属性，复杂度 O(log N)。
`protect` 对一个已有区间的子区间变更属性，必要时保留左右片段；
`erase` 可跨多个区间及空洞删除，并归还与合并空闲区间。
它们在修改树前取得全部分裂节点，元数据不足时原区间和属性均保持不变。
属性相同的独立预留仍保留各自边界，使 exact release 的分配身份明确。
`copy_to` 先复制完整地址窗口和已占用记录到候选池，成功才交换目标；自复制无操作。
显式 `swap/reset` 用于 exec 提交、销毁和失败回滚。

`release(begin)` 只接受已分配区间的准确起点，拒绝内部地址、未知地址和重复释放。
归还时复用已有节点，并与相邻空闲区间合并，不申请物理内存，因此物理内存耗尽时仍可归还区间。
合并优先保留已有空闲区间描述符。精确查找和单区间释放为 O(log N)；跨 K 个已占用区间的删除为 O((K+1) log N)。
区间节点现由 memory 模块的共享精确尺寸 slab 缓存提供，不再由每个池维护一组元数据页和备用链表。
这避免了小地址空间各自占一整页：契约测试中的 1000 个独立小池共使用 37 个物理元数据页。
每个池只负责自己的树节点；节点从树中摘除后才归还 slab。同页其他池仍有节点时，页面不会被回收。
`reset()` 释放该池全部节点，最后一个使用者归还槽位时释放物理页，不替调用方撤销页表映射。
接口及缓存选择见 [slab 对象分配](slab.md)。

## 内核栈接入

`KernelPageTable` 为整个低半 Sv39 地址空间建立一个池，固定映射通过指定地址预留。
栈分配限制在实际 RAM 末端向上对齐后到 `KSTACK_TOP` 之间的窗口。
每次申请 `2 * KSTACK_BYTES`，前半作为等大无映射保护区，后半作为栈。
删除固定槽公式、槽位数量及位图，不再启动时预建整个栈窗口的上级目录。
空闲区间表示尚未使用的地址空间，无需为每个潜在栈支付物理页或页表成本。

栈创建仍通过原 AllocateFlow 执行：区间申请及保护区属性、栈属性拆分、完整叶表准备、初始 32 KiB 提交、发布。
任一步失败都撤销已创建的叶表及数据帧、区域登记与区间占用。
共享上级目录按需建立。运行栈生命周期同时固定其叶表和上级目录；回收在区域锁内进行，
仅当上级目录已没有任何有效子项时才摘除、刷新 TLB 并释放，因此不影响其他运行栈的无锁遍历。
部分准备失败留下的空上级目录同样回收，不保留失败尝试的物理页成本。

首个栈目录 PTE 的 RSW bit 9 是发布标记。该位不用于用户 COW 的 bit 8，
不参与物理地址编码；栈的所有准备完成后以 release 操作置位。
运行栈由当前进程或 hart 生命周期固定，缺页处理以 acquire 读取稳定目录及发布标记，
只使用预建叶表及调用方提供的取帧回调，不查询红黑树、不取得管理锁，也不分配区间元数据。
底层遍历以 acquire/release 读取和发布新目录。

回收要求使用者已经停止运行并完成原有锁交接，先断开栈目录、刷新本核 TLB，
再释放栈数据页、独占叶表和已经为空的上级目录，在统一池中删除栈与保护区并归还区间。区域查询与统计继续由栈管理锁保护；
统计中的叶子数量仍是观测值。当前没有新增共享地址空间线程或远程 TLB shootdown 协议。

地址池容量由地址窗口决定，并非无限。当前内核仍为每个栈配置固定预留容量和等大保护区；
按需增长仅在该容量内提交物理页，不跨越保护区自动扩容。进程数量还受进程表及物理内存约束。
物理 RAM 的既有平台上界保持不变。

## 验证

- 两种物理分配器上的实际地址池代码：20000 次随机操作对照模型、40000 次独立分配、
  超过旧槽数量、碎片化与双侧合并、精确匹配、耗尽、非法释放、元数据 OOM 原子性、空元数据页即时回收与完整 reset 回收。
- 实际 RISC-V 页表和分配器：私有 QEMU 探针以 256 MiB RAM 创建 1000 个内核栈，释放交错区间并复用，
  检查已释放栈不能补页，以及首轮和重复完整周期后空闲物理页精确恢复；这是内核栈规模测试，不是 1000 进程测试。
- 私有 QEMU OOM 探针：耗尽物理页后逐步提供不同页预算，验证部分准备/提交失败时的回滚及地址复用。
- 原持锁增长、只读栈页、应急池耗尽和保护区故障探针继续保留。

不运行独立 fork 计时或 `fork_progress`。最终验证命令及结果另记录在
`docs/virtual-address-pool-acceptance.json`；既有流程迁移验收记录属于先前提交的历史证据。

本次统一迁移的验证记录见 `docs/unified-address-pool-acceptance.json`；此前验收记录保持为历史证据。
